# 产品资产生成

输入是产品资料、可选的指定款色与形态基准。交付一个版本目录，包含独立高清 PNG 和一份 UTF-8 `资产说明.txt`。Agent 根据每张图的产品自然形态、拍摄角度和证据用途独立选择画幅，同一图组可同时包含横图、竖图和方图。用户明确指定的尺寸优先；与关键证据完整性冲突时说明取舍并确认。结束时提供版本目录、各图链接及用途；若用户想继续替换，提示另行提供目标场景和这套资产。

普通任务入口先执行 `node <本 Skill 目录>/.runtime/bin/product-asset-set.mjs prepare --json`，进行有界更新检测及本地诊断；源码开发使用包内 bin 入口。父集合管理的安装由所属集合统一更新。安装、更新和恢复遵循包根目录 INSTALL.md / UPDATE.md，执行入口为当前目标自有运行时。

1. **核对来源与形态。** 逐个打开实际文件，记录路径、编号、哈希和观察。每个查看结果与同次调用的文件标识绑定；文件名与描述冲突时，单独重开该文件核实。详情页查看全部商品相关区域，必要时按原像素裁切。比较轮廓、比例和可见结构，区分透视、遮挡与正常受压。如果有真实冲突或无法排除冲突，展示对应原图，等待用户指定基准对象；已有明确选择则复用。记录基准与相关素材各自的证据职责。
2. **规划独立图片。** 至少包含一张完整全貌（`overall`）和一张有可辨参照物或人物的相对尺度（`scale`）。按新增证据规划 `structure`、`texture`、`marking` 或 `use`。同一用途优先留最清楚的一张。为每张分配稳定编号，列出画幅、目标尺寸、选择理由、证据来源、保留内容、编辑范围和验收点。先确定产品与必要参照物的自然朝向，再选择能完整容纳主体且主体占比足够的画幅。横向长条产品全貌优先评估 16:9 或 3:2，竖向产品或人物使用图优先评估 3:4、2:3 或 9:16，紧凑全貌和局部细节可用 1:1 或 4:3；按实际内容选择。产品的摆放、姿态和比例服从原始参考，避免为了适配画幅而旋转成长对角线、悬浮或改变产品形态。源图缺少必要证据时请求补图，可交付清楚标明缺口的阶段性预览。
3. **先全貌，再逐张制作。** 优先用原照片和原人物、动作、场景。需要生成时，发现当前宿主的参考图编辑能力，核对所选画幅、服务支持的尺寸和费用，按授权每次生成一张。先对照原始基准验收全貌，再做依赖该全貌的图片。使用场景图由原图提供人物和使用关系，产品身份由基准参考提供。提示词聚焦构图和必要编辑，产品结构与材质服从参考。记录每张实际输出尺寸和比例。实际比例与计划略有偏差时，先看完整性与主体可读性；需要精确比例时仅采用保留关键证据的等比整理。逐张查看真实结果，验收身份、用途、清晰度和主体占比。每次调用记录原始输入、请求、可用的真实任务标识和结果；未知提交先查原任务。
4. **打包、修订和定稿。** 按 [资产交接协议](references/asset-format.md) 构建说明并检查每个文件。技术验收通过后交给用户确认。局部修订创建新版本目录，复用其余已通过原件并比对哈希，只改对应编号与说明；更改形态基准时重新核对受影响图片。定稿依据为用户真实确认，记录在资产交付目录外。

运行记录随项目保存，依次记录来源核对、图片计划、各编号的制作及验收、交付及确认。保留失败图与历史版本，展示给用户时提供每个业务阶段的结果和可打开的证据。
