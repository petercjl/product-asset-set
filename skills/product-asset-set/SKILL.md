# 产品资产生成

输入是产品资料、可选的指定款色与形态基准。资产用于后续参考图生图，需在原生像素下清楚提供商品身份、尺度或材质证据。交付一个版本目录，包含独立高清 PNG 和一份 UTF-8 `资产说明.txt`。Agent 根据每张图的产品自然形态、拍摄角度和证据用途独立选择画幅，同一图组可同时包含横图、竖图和方图。用户明确指定的尺寸优先；与关键证据完整性冲突时说明取舍并确认。结束时提供版本目录、各图链接及用途；若用户想继续替换，提示另行提供目标场景和这套资产。

普通任务入口先执行 `node <本 Skill 目录>/.runtime/bin/product-asset-set.mjs prepare --json`，进行有界更新检测及本地诊断；源码开发使用包内 bin 入口。父集合管理的安装由所属集合统一更新。安装、更新和恢复遵循包根目录 INSTALL.md / UPDATE.md，执行入口为当前目标自有运行时。

1. **核对来源与形态。** 逐个打开实际文件，记录路径、编号、哈希和观察。每个查看结果与同次调用的文件标识绑定；文件名与描述冲突时，单独重开该文件核实。详情页查看全部商品相关区域；可临时截取局部供核对来源和定位证据。比较轮廓、比例和可见结构，区分透视、遮挡与正常受压。如果有真实冲突或无法排除冲突，展示对应原图，等待用户指定基准对象；已有明确选择则复用。记录基准与相关素材各自的证据职责。
2. **规划独立图片。** 每套成品至少生成三张独立资产，各承担一项必备任务：**产品全貌**（`overall`）完整呈现外轮廓和比例；**尺寸参考**（`scale`）通过可辨人物或参照物呈现相对大小，有实测尺寸或商品规格时在资产说明中注明来源；**材质近景**（`texture`）以产品表面为主体，清楚呈现原图可核实的纹理和质感。按新增证据补充 `structure`、`marking` 或 `use`。同一用途优先留最清楚的一张。为每张分配稳定编号，列出画幅、目标尺寸、选择理由、证据来源、保留内容、编辑范围和验收点。先确定产品与必要参照物的自然朝向，再选择能完整容纳主体且主体占比足够的画幅。横向长条产品全貌优先评估 16:9 或 3:2，竖向产品或人物使用图优先评估 3:4、2:3 或 9:16，紧凑全貌和局部细节可用 1:1 或 4:3；按实际内容选择。产品的摆放、姿态和比例服从原始参考，避免为了适配画幅而旋转成长对角线、悬浮或改变产品形态。源图缺少必要证据时请求补图，可交付清楚标明缺口的阶段性预览。
3. **先全貌，再逐张制作。** 优先选最清晰、同款同色的原图作为事实基准。默认使用当前宿主的参考图生成或编辑能力制作面向后续生图的独立资产，核对原生输出尺寸与费用，每次制作一张。全貌应完整、主体占比充分、轮廓易读，背景服务于辨识；人物尺度图沿用原图的可核实姿态、接触和相对比例；材质图用独立近景呈现原图可核实的纹理。提示词聚焦构图、焦点、光线与用途，商品身份与可见结构服从基准。用户要求重新生成时按用途重新调用生图能力。完整原图可作为补充证据，注明来源；裁剪片段、简单转格式与插值放大不作为制作高清资产的替代方案。源图缺少身份或关键细节证据时请求同款清晰原图，并交付已验收部分；生成结果不能补作事实证据。

   **逐张验收。** 在原生像素下同时核对清晰度和产品一致性。记录实际尺寸、画幅、主体占比与关键区域可读性，优先选用宿主支持的高清原生输出；预览图变大不能证明细节增加。边缘、纹理或尺度证据须按用途可辨，同时与原始参考逐项核对轮廓、比例、颜色、材质和可见结构。先通过全貌验收再制作依赖图；不合格图标记原因，针对该问题重试或请用户补图。能力不可用或证据不足时明确缺口。记录每次调用的原始输入、请求、真实任务标识（若可得）、结果与验收状态；未知提交先查原任务。
4. **打包、修订和定稿。** 在资产说明中区分生成图与完整原图，标注来源、用途和局限。商品页规格等事实单独引用原始证据。按 [资产交接协议](references/asset-format.md) 构建说明并检查每个文件。三项必备资产均通过技术验收后，作为完整图组交给用户确认。局部修订创建新版本目录，复用其余已通过原件并比对哈希，只改对应编号与说明；更改形态基准时重新核对受影响图片。定稿依据为用户真实确认，记录在资产交付目录外。

运行记录随项目保存，依次记录来源核对、图片计划、各编号的制作及验收、交付及确认。保留失败图与历史版本，展示给用户时提供每个业务阶段的结果和可打开的证据。
